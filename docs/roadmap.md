# План реализации

Каждый этап заканчивается работающим сценарием. Этапы не являются оценкой сроков.

## 0. Основание — текущий этап

- Монорепозиторий, React, health API, TypeScript, lockfile и CI.
- Документы со стеком, границами MVP и правилами Git.
- Готово, когда чистая установка, типы, тест и сборка проходят.
- Публикация GitHub остаётся отдельным действием: удалённый репозиторий не выбран.

## 1. Каталог и UX одного участника

- Прототип экранов комнаты, ответов, подбора и результата.
- Небольшой проверенный набор игр и признаки режимов.
- Компоненты Button, Field, GameCard, Participant, EmptyState.
- React Router, формы, Zod; доступность с клавиатуры и мобильный экран.
- Готово, когда можно пройти ответы и увидеть результат на демонстрационных данных;
  демонстрационный режим явно подписан.

## 2. Сохранённая комната

- PostgreSQL, Drizzle, миграции и seed каталога.
- Гостевая cookie-сессия, создание комнаты, приглашение, вступление, снимок комнаты.
- REST-контракты, серверная валидация, лимиты, права хоста и участника.
- TanStack Query; загрузка, ошибка, повтор запроса и истёкшее приглашение.
- Готово, когда два независимых браузера входят в одну комнату, а обновление
  страницы сохраняет участника. Попытки изменить чужие ответы отклоняются.

## 3. Объяснимый подбор

- Чистый matching-пакет, обязательные ограничения и мягкие предпочтения.
- Причины исключения, неизвестные данные, пустой результат, стабильное ранжирование.
- Тесты: разное число игроков, нет общего времени, неизвестная установка,
  veto, равные оценки, ни одного подходящего варианта.
- Готово, когда результат воспроизводится из входных данных, а UI объясняет его.

## 4. Совместный выбор

- Socket.IO, авторизация подписок, версии снимков и refetch после reconnect.
- Голосование, номер раунда, подтверждение готовности, сброс при изменении условий.
- Тесты конкурирующих команд и Playwright-сценарий нескольких контекстов браузера.
- Готово, когда изменение условий появляется у всех, reconnect восстанавливает
  актуальное состояние, а устаревший голос не подтверждает новый раунд.

## 5. Портфолио и публикация

- Проверка клавиатуры, контраста, мобильного интерфейса и сетевых ошибок.
- CI: добавить UI/E2E-проверки на появившиеся сценарии.
- Production-конфигурация, HTTPS, миграции, резервное копирование и инструкция запуска.
- Демокомната, скриншоты, короткое видео и README с архитектурными компромиссами.
- Готово, когда другой человек запускает проект по README и проходит основной сценарий.

## 6. Steam — после самостоятельного MVP

- Проверить доступ и условия API, приватные/пустые библиотеки и free-to-play.
- Импорт, кеш, ручное исправление, timestamp последней синхронизации.
- Ошибка Steam не должна блокировать ручной сценарий.
- Измерить на игровых вечерах: время до выбора, долю завершённых комнат,
  причины отсутствия результатов. Сбор аналитики проектировать отдельно и прозрачно.
