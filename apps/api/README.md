# PartyPick API

Локально используется PostgreSQL/WASM (PGlite), данные сохраняются в `apps/api/.data`.
`PGLITE_DATA_DIR` меняет каталог; значение `memory://` даёт временную БД для тестов.
Одновременно каталог может использовать только один процесс API.

При `DATABASE_URL` сервер подключается к обычному PostgreSQL через `pg`.
Проверки интеграции в этой итерации выполнены на PGlite; отдельный внешний PostgreSQL
не был доступен. При старте выполняется идемпотентная начальная SQL-миграция.

## Размещение

Production требует `NODE_ENV=production` и `PUBLIC_ORIGIN`, например
`https://partypick.example`. Клиент и `/api` должны быть под одним HTTPS origin.
Reverse proxy обязан сохранять публичный `Host`: проверка изменяющего запроса
сравнивает `Origin` с `PUBLIC_ORIGIN`, а hostname `Host` с тем же публичным адресом.
Чужие Origin и Host отклоняются. Cookies используют Secure, HttpOnly, SameSite=Lax.

Сервер не доверяет произвольным `X-Forwarded-*`. Лимиты запросов сейчас считаются
по реальному peer IP: 12 созданий и 30 вступлений в минуту, 1200 чтений снимка
комнаты в минуту для совместного polling, остальные маршруты — 300/мин.
Для размещения за общим proxy нужен отдельно настроенный доверенный proxy/CIDR
и проверка лимитов в реальной сети; включать безусловный trustProxy нельзя.
До нескольких API-экземпляров необходимо вынести limiter в общее хранилище.

Комната живёт 24 часа, гостевая сессия — 7 дней. При рестарте просроченные записи
удаляются. Структура комнаты хранится JSONB-агрегатом; изменения блокируют строку
в транзакции и проверяют version/round. Снимки выдаются только участникам,
ссылка приглашения — только ведущему. Запросы с capability URL не логируются.
