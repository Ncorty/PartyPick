# PartyPick

**Выбрать игру на вечер, в которую сможет сыграть вся компания.**

PartyPick собирает пожелания участников, проверяет общие игры и помогает договориться
о выборе. Учитываются наличие и установка игры, размер компании, режим, доступное
время и личные предпочтения. Интерфейс — пиксельное лобби из тёмной RPG.

## Как это работает

1. Ведущий создаёт приватную комнату и делится ссылкой приглашения.
2. Участники указывают доступные игры и пожелания на вечер.
3. Сервис предлагает подходящие варианты и объясняет причины исключения остальных.
4. Компания голосует, ведущий подтверждает результат, участники отмечают готовность.

Если условия изменились, можно вернуться к пожеланиям и начать новый раунд.
Регистрация для гостевых комнат не требуется.

## Что уже работает

- Приватные комнаты для 2–8 участников с приглашениями и гостевыми сессиями.
- Каталог из шести игр с ручным указанием наличия и установки.
- Подбор с объяснениями и ранжированием по предпочтениям всей компании.
- Голосование, результат, готовность, выход участника и повторные раунды.
- Сохранение комнат между перезапусками API.
- Обновление состояния, проверка прав ведущего и обработка одновременных изменений.
- Адаптивный интерфейс для компьютера и телефона.

На главной показан подписанный пример. Настоящий сценарий начинается
с кнопки «Создать комнату».

## Быстрый старт

Нужны **Node.js 22.12+** и **npm 10+**. Отдельно устанавливать PostgreSQL
для локальной разработки не требуется.

```sh
git clone https://github.com/Ncorty/PartyPick.git
cd PartyPick
npm ci
npm run dev
```

Откройте [localhost:5173](http://localhost:5173).
API работает на `http://127.0.0.1:3001`, проверка состояния — `/api/health`.
Vite перенаправляет запросы `/api` на сервер.

Чтобы пройти весь сценарий самостоятельно, откройте приглашение в другом профиле
браузера или приватном окне. Обычные вкладки одного профиля используют общую сессию.

Данные сохраняются в `apps/api/.data`, этот каталог исключён из Git.
Один каталог данных может использовать только один процесс API.
Локальная ссылка доступна на вашем компьютере; для приглашений между устройствами
нужно размещение приложения под общим адресом.

## Стек и устройство проекта

| Часть                  | Технологии                                     |
| ---------------------- | ---------------------------------------------- |
| Интерфейс              | React, TypeScript strict, Vite, Tailwind CSS   |
| Маршрутизация и данные | React Router, TanStack Query                   |
| API                    | Fastify, Zod, cookie-сессии                    |
| Хранение               | PGlite локально, адаптер PostgreSQL через `pg` |
| Проверки               | Vitest, Playwright, ESLint, Prettier           |
| Организация            | npm workspaces, FSD на frontend                |

```text
apps/
  web/src/
    app/             # роутер, провайдеры и глобальные стили
    pages/           # главная, создание комнаты, приглашение и комната
    shared/          # UI, API-клиент, изображения и шрифты
    main.tsx         # точка входа React
  api/src/           # HTTP API, гостевые сессии и работа с БД
packages/
  contracts/         # общие типы, схемы валидации и каталог игр
  matching/          # подбор и объяснение результатов без зависимости от UI
config/              # общие frontend-алиасы Vite и Vitest
tests/e2e/           # браузерные сценарии
```

Направление зависимостей FSD: `app → pages → widgets → features → entities → shared`.
Слои `widgets`, `features` и `entities` появятся по мере выделения общего кода;
пустых директорий для них сейчас нет. Слайсы экспортируют публичный API через
`index.ts`, внутри слайса используются относительные импорты.

Для всего `src` настроен `@/*`. Для слоёв доступны `@app/*`, `@pages/*`,
`@widgets/*`, `@features/*`, `@entities/*` и `@shares/*` → `shared/*`.
Настройки согласованы между TypeScript, Vite и Vitest.

## Команды разработки

Все команды выполняются из корня репозитория.

| Команда                | Назначение                                                   |
| ---------------------- | ------------------------------------------------------------ |
| `npm run dev`          | Собрать общие пакеты и запустить frontend вместе с API       |
| `npm run build`        | Собрать общие пакеты, API и frontend                         |
| `npm run typecheck`    | Проверить типы приложений, пакетов и тестовой инфраструктуры |
| `npm run lint`         | Проверить код ESLint                                         |
| `npm run format:check` | Проверить форматирование                                     |
| `npm run format`       | Отформатировать файлы                                        |
| `npm test`             | Запустить тесты подбора, API и хранения                      |
| `npm run test:e2e`     | Пройти браузерные сценарии                                   |

Перед первым запуском E2E установите браузер:

```sh
npx playwright install chromium
npm run test:e2e
```

E2E поднимают отдельные серверы на портах **5175** и **3003** с временной БД.
Они проверяют совместный сценарий в независимых сессиях: приглашения,
подбор, голосование, готовность и восстановление после ошибок.
Тесты API покрывают доступ, конфликты версий, сохранение и лимиты запросов.

Сборки находятся в `apps/web/dist` и `apps/api/dist`.
Собранный API запускается командой `npm run start -w @partypick/api`.
Он не раздаёт frontend: для размещения нужны раздача статики и проксирование `/api`.

## Ограничения MVP

- Комната живёт 24 часа. Восстановления гостевого доступа после удаления cookie пока нет.
- Наличие игр указывается вручную; подключения к игровым аккаунтам пока нет.
- Каталог описывает поддерживаемые игровые профили без модификаций.
  Время сессии приблизительное, произвольные серверные настройки не учитываются.
- Состояние обновляется опросом API раз в секунду.
- Хранение проверено на PGlite. Подключение к внешнему PostgreSQL предусмотрено,
  но отдельная интеграционная проверка пока не выполнена.

Переменные окружения, подключение PostgreSQL, HTTPS, cookies и требования
к reverse proxy описаны в [документации API](apps/api/README.md).
